# 简报输出模板

## 重要性分级

| 标记 | 含义 | 判据 |
|---|---|---|
| 🔴 | 重大 | 改变竞争格局或技术路线：前沿模型发布、10 亿美元级融资、重大人事/监管变动 |
| 🟡 | 值得关注 | 有实质增量信息：常规模型迭代、亿元级融资、有数据支撑的评测、值得读的技术文章 |
| ⚪ | 简讯 | 知道即可：产品小更新、未证实传闻、预告类消息 |

一份日报里 🔴 通常 0-2 条。**如果标了 5 条 🔴，说明分级失效了**，重新压。

## 条目格式

```markdown
- 🔴 **[标题：一句话说清发生了什么]** `2026-08-01`
  [2-4 句展开：谁、做了什么、关键数字、为什么重要。有争议或来源冲突就在这里并列。]
  来源：[机器之心](url) · [TechCrunch](url)
```

写条目的几条规矩：

- **标题是结论不是话题**。写「Kimi K3 开源，2.8 万亿参数 MoE」，不写「Kimi 有新动作」
- **数字进标题**。融资金额、参数量、评测分数——有就往标题放
- **日期用 `YYYY-MM-DD`**，确认不了就写 `（日期未确认）`，别写"近日"
- **来源 2-3 个封顶**，多了没用。中英文源都有时优先各留一个
- **不要写"值得持续关注"这类废话结尾**

## 变体

**日报**（近 24-48h）——砍掉板块内的中国/全球二级标题，条目总数控制在 8-12 条，
GitHub Trending 用 `since=daily`。

**周报**（近 7 天）——保留全部结构，加融资一览表，
「本期要点」写成 5-7 句并点出本周主线（比如"本周主线是算力价格上涨传导到创业公司融资节奏"）。

**专题**（用户指定话题）——丢掉三板块结构，改成：
`事件时间线 → 各方表态 → 数据/事实核查 → 尚不清楚的部分`。
最后一节必写，专题最容易在这里露怯。

## 空板块怎么处理

某个板块确实没查到东西时：

```markdown
## 💬 社媒 / 社区热议

本期未检索到有实质信息量的社区讨论。（已检索 zhihu / v2ex / news.ycombinator，
返回结果均为旧帖或泛论，无近期热点。）
```

**照实写空，不要用陈年旧闻或泛泛而谈的条目把版面填满。**
一份诚实的两板块简报，比一份三板块但有一块是凑数的简报有用。
